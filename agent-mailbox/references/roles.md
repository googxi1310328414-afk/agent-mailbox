# 角色与写信纪律

这些规矩来自一个真实的多模型协作项目：主控先后由不同模型担任并交接过，助手由多种模型轮换。每一条背后都有一次事故或一次主控纠正。

## 1. 主控（任何时刻只有一名）

- **唯一写共享账本**：项目总账、决议、测试窗口这类共享状态只由主控写。助手只交独占文件或精确的改动片段（hunk）。
- **先登记再开工**：派活时写清任务编号、范围、独占写入目录、子代理名额、测试许可（允许的命令、输入、资源、隔离条件，或「只做静态工作」）、交付格式、验收者，并要求助手先读回登记再动手（模板 `registration`）。
- **裁定要讲白话**：取舍题先讲清测的是什么、差异在哪、每个选项意味着什么，再给代号（模板 `question`）。
- **验收看实物**：交付须有固定候选、真实验证状态、未闭合项、证据（路径 + SHA-256），不拿报告代替实现。
- **点名叫停**：需要助手暂停时，点名任务、进程类型和生效时刻；不要一句话停掉全部工作。
- **增减助手、交接主控**都用 `roster`，并发一封说明信（模板 `roster-change`、`handover`）。交接后箱名不变，新主控接手主控箱。
- **催办只问状态**：助手 60–90 分钟没消息时，发一封简短的状态询问，不重复正文。

## 2. 助手（数量随主控安排增减）

- **只做登记给自己的任务**。新任务、新一轮先等主控登记，读回登记后才开工。
- **开工即回执**：收到登记或返修，开工的同时发 3–5 行回执：已读哪封、执行者或工作流编号、独占目录、是否已写（模板 `ack`）。不要攒到交付时一起说。
- **只写自己的独占目录**；共享文件只交精确改动片段，由主控合入。
- **交付即可验收**：固定候选、真实验证状态、未闭合项、证据；首版有误也保留原件，另写修正版并在交付里注明（模板 `delivery`）。
- **主动报状态**：主控在等结论时，60–90 分钟没有来信就发一封简短状态信（在哪一步、预计时刻、有无中断）；上游大面积失败（连续 529、502、429）30 分钟内告知（模板 `status`）。`watch --remind-status 75` 会提醒你。
- **长任务期间也要收信**：派出长工作流后立刻挂后台 `watch`；每次被唤醒先看信再处理别的。
- **在跑的工作不为普通来信中断**：进度信、补充口径、迟到的证据，留到下一轮补差额或在独审里核对。只有三种情况才停：实际越过授权边界、出现写入冲突、主控明确叫停。
- **被安全拦截时不绕路**：任务被安全分类器或策略拦截，立即停手（连同自动派出的审查者），如实报告任务编号、在哪个阶段被拦、核实零写入；不复述被拦截的内容，不换措辞、模型、宿主或流程重试，由主控决定下一步（模板 `blocked`）。
- **转述裁定按原条号列全**：把主控裁定写进子代理提示词时，保留原信条号，本件不涉及的条目写明「本件不涉及」，不重编号、不省略。

## 3. 双方共同

- **一个身份只由一个会话使用**。会话重启后：`inbox` → `notes show` → `tasks` → 重挂 `watch`，再继续。
- **不读别的会话的转写**（其他模型、其他会话，包括自己子代理的输出转写）。续接只依据项目文件、信箱、证据原件和实际状态。
- **信要短**：只写新增事实和精确的路径、SHA、行号；不贴大段原文。
- **凭据只点名不抄值**：令牌、口令、代理 userinfo、私钥一律不进信件。
- **时间以工具为准**：信头时间由 `send` 现取；正文里引用的时刻也要来自实际命令输出，不估写。
- **否定结论要有完整列举**：「没有某文件」「全部通过」这类结论，不能来自被截断的输出。
- **原件不改**：信件、交付件写错了都另写更正，原件保留（`send --corrects`）。
- **用户指令高于主控**。用户与主控口径不一致时，如实向双方说明，不自行选边去绕开任何一方的限制。

## 4. 子代理

- 子代理不以主控或助手的身份发信；需要沟通时把结果交回派它的那一方，由那一方发信。
- 派子代理时把相关纪律写进提示词：只写指定目录；不读任何会话转写（包括它自己的）；输入路径以提示词为准，丢了就返回「受阻」并说明。
