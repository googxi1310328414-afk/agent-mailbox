# 信箱协议 agent-mailbox/1

本文是协议本身，`scripts/mailbox.py` 是它的参考实现。任何语言、任何客户端，只要按本文读写同一目录，都能与它混用；`adapters/` 下的客户端外壳只是调用这个脚本。

## 1. 目录

信箱是一个**平铺目录**，几方都能读写（同机共享盘，或 WSL 经 `/mnt/<盘>` 访问同一目录）。

| 位置 | 内容 | 谁写 |
|---|---|---|
| `to-*.md` | 信件，一封一个文件，写成后永不改动 | 发信方（只经投递算法创建） |
| `to-*-STATUS.json` | 状态板：长任务的实时快照，整文件原子替换 | 板的写入方 |
| `.agent-mailbox/config.json` | 花名册与设置 | 只有主控或用户（`roster` 子命令） |
| `.agent-mailbox/cursors/<名>.json` | 各参与方的已提醒、已读集合，监视状态 | 本人 |
| `.agent-mailbox/tasks/<名>.json` | 任务清单、等待对象、等待文件 | 本人 |
| `.agent-mailbox/notes/<名>.md` | 续接备忘 | 本人 |
| `.agent-mailbox/presence/<名>.json` | 监视进程登记（pid、主机、心跳） | 本人的 `watch` |
| `.agent-mailbox/locks/*.lock` | 编号锁、游标锁、花名册锁（毫秒级持有） | 工具 |
| `.agent-mailbox/log/sent.jsonl` | 投递日志：时间、发件、收件、文件、SHA-256 | 工具（只追加） |
| `.agent-mailbox/log/roster.jsonl` | 花名册改动日志 | 工具（只追加） |

控制目录可用 `--state-dir` 放到别处（例如只读体检时指向临时目录）；但编号锁要对所有写信方可见，正式使用时放在信箱里。

## 2. 信件文件名

```
to-<收件箱>-<线程>-<编号>[-URGENT].md
```

- **收件箱**（box）：小写字母数字，可用 `-` 连接，如 `codex`、`claude`、`kimi-1`。
- **线程**：8 位小写十六进制，区分同一目录里的不同协作。旧式无线程文件 `to-<箱>-<编号>.md` 只读兼容（花名册 `include_threadless: true` 时列入）。
- **编号**：按「箱 + 线程」各自递增，至少 3 位补零（`001`），超过 999 自然变长（`1273`）。同一编号只属于一封信，**不论后缀**：`338.md` 与 `338-URGENT.md` 并存算撞号。
- **后缀**：本工具只生成 `-URGENT`（紧急）；解析时接受 `[-_][A-Za-z0-9_]+` 形式的任意后缀。
- 引用一封信：`941`（在本方各箱里找）、`claude-941`、`codex-338-URGENT`，或完整文件名。

## 3. 收件箱与路由

| 箱 | 归属 | 谁收 |
|---|---|---|
| 主控箱 `controller_box` | **角色**，不属于某个人 | 在任主控收全部来信；交接后新主控接手，箱名不变 |
| 个人箱 `box` | 参与方 | 箱内在任成员；一人独占时不必看标题 |
| 共享箱 | 几个参与方填同一个 `box` | 按标题点名区分 |
| 广播箱 `broadcast_box`（默认 `all`） | 全体 | 全体在任参与方 |

路由依据：本工具投的信在信头「收件：」里写参与方名，收信方按它判断；只有旧信（或别的工具写的信）才回退到解析标题。

标题点名规则：
- 新信标题一律 `# 致 <称呼>[、<称呼>…]：<主题>`。称呼可以是参与方名、显示名、别名，或角色词（`主控`、`全体`、`全体助手`）。
- 称呼按「在任者优先、最长匹配优先」解析；称呼后紧跟的不能是字母数字（`agent-main-20260101` 能匹配 `agent-main`，`pipeline` 不匹配 `pi`）；解析不出时再看其中的 8 位会话号。
- 兼容旧式标题：`# A → B 编号：…`、`# Codex 602：致 X，…`、无 `#` 的首行。

对收件人 X，一封信分为四类：

| 类 | 条件 | `inbox` | `watch` |
|---|---|---|---|
| mine | 标题点名 X（或 X 所属角色词）；或在 X 的独占箱、未点名；或 X 是在任主控且信在主控箱 | 列出 | `MAIL` |
| all | 广播箱里未点名或点名「全体」 | 列出 | `MAIL-ALL` |
| shared | 共享箱里标题没点名任何人 | 列出，标 `[共享]` | `MAIL-SHARED` |
| other | 标题点名的是别人 | 默认不列（`--others` 才列） | 摘要附带（`--others trigger` 才唤醒） |

自己发的信不算自己的未读，也不唤醒自己。

## 4. 信件格式

```
# 致 claude-a：登记 T-123（只读核对）

发件：lead（主控，gpt-5.5，any，会话 7f3a9c21）｜时间：2026-10-26 18:56:32（北京）/ 2026-10-26T10:56:32Z｜编号：to-claude-5e1f0a2b-042｜回复：to-controller-5e1f0a2b-071

正文（Markdown）……

## 附件（投递时实算）

| 文件 | 字节 | SHA-256 |
|---|---|---|
| `D:/run/REPORT.md` | 4674 | `0f14…` |
```

- 第 1 行标题，空一行，第 3 行信头，空一行，正文。
- 信头字段以 `｜` 分隔：`发件`（必有）、`收件`（必有，参与方名，路由以它为准）、`抄送`、`时间`（必有，投递当刻现取，本地时区与 UTC 各一）、`编号`（必有，即文件名去掉 `.md`）、`回复`、`更正`、`紧急`。
- 读旧信时也认 `发信：`、`发信方：`、`发件人：`、`From:`。
- 编码：UTF-8、LF、无 BOM；不得含 U+FFFD；默认上限 64 KB（`max_bytes`）。
- 不得含凭据：内置规则拦截 `sk-`/`sk-ant-` 密钥、`Bearer` 令牌、私钥块、GitHub/AWS/Slack 令牌、JWT；花名册 `secret_patterns` 可追加项目自己的规则。
- 草稿里可写 `{{NUM}}`、`{{FILE}}`，投递时替换成实际编号和文件名。

## 5. 投递算法（排他、不覆盖）

1. 卫生检查：UTF-8、无 BOM、无 CR、无 U+FFFD（`--normalize` 可自动去 BOM、换行改 LF）；渲染后再查大小和凭据。多箱投递先整体校验一遍，避免投了一半才报错。
2. 取编号锁 `locks/send-<箱>-<线程>.lock`（O_EXCL；持有者已死或超过 10 秒视为陈旧；等锁的一方先只看文件年龄，不在持有期间打开它）。锁只用来缩小并发窗口，拿不到时退回为只靠排他创建。
3. 列出同箱同线程**全部后缀**的已用编号，取最大号加一（`--start N` 时取不小于 N 的第一个空号，与「按起始号投递」的旧脚本相同）。
4. 以 `open(path, 'xb')`（Node 为 `flag: 'wx'`）排他创建并一次写入；已存在就把该号记为占用、重新列目录、顺延，最多试 `max_tries` 次。
5. 创建后复查同号的其它后缀文件（防止与不认锁的旧工具同时取到同号）：无后缀者优先，同类按文件名先后；本信该让号时，确认读回内容仍是自己写的才删除，然后顺延重投。这一步只能兜住「对方的文件在本信复查时已经存在」这一种先后顺序：若本信先写了 `NNN-URGENT.md`，只认无后缀文件名的旧工具在复查之后才写 `NNN.md`，仍会同号。`doctor` 会报「同号多信」，引用这类信时要带后缀或写完整文件名。
6. 读回整文件，与写入字节比对，报告字节数与 SHA-256。
7. 追加 `log/sent.jsonl`；更新发件人游标的 `last_sent`。

信一经投递**永不修改、永不删除**。写错了另投一封，信头带 `更正：<原信>`。

## 6. 状态板

```
to-<箱>-<线程>-<KEY>-STATUS.json        KEY：大写字母数字，可用 - 连接，如 PINWIN-W1
```

- 写入：`status put KEY --file x.json`（默认写进主控箱，`--to` 指定别人），整文件原子替换；工具加一个 `_mailbox: {writer, writtenAtUtc}` 字段。
- 用途：长时间执行的进度快照（步数、当前步、最近终态、进程是否存活）。约定每 ≤4 分钟替换一次；它只是快照，原始回执以执行目录为准。
- 不占信件编号，`watch` 不为它唤醒。

## 7. 花名册 config.json

| 字段 | 含义 | 默认 |
|---|---|---|
| `schema` | 固定 `agent-mailbox/1` | |
| `revision`、`updated_at` | 每次改动加一 | |
| `thread` | 8 位十六进制线程号 | 随机 |
| `timezone`、`timezone_label` | 信头本地时间 | `+08:00`、`北京` |
| `controller_box`、`broadcast_box` | 主控箱、广播箱 | `controller`、`all` |
| `include_threadless` | 是否列入旧式无线程信 | `false` |
| `max_assistants` | 在任助手上限（可调） | 8 |
| `max_bytes`、`max_tries`、`pad` | 信件上限、顺延次数、编号最少位数 | 65536、50、3 |
| `policy.assistant_to_assistant` | 助手互通：`allow` / `cc-controller`（自动抄送主控）/ `deny` | `allow` |
| `policy.broadcast` | 谁能广播：`controller` / `anyone` | `controller` |
| `policy.inactive_send` | 不在任者能否发信 | `deny` |
| `secret_patterns` | 追加的凭据正则 | `[]` |
| `participants[]` | 参与方：`name`、`role`（controller / assistant / former / observer）、`display`、`model`、`harness`、`session`、`box`、`aliases`、`active`、`since`、`until`、`note` | |

校验（不通过就拒绝写入）：恰有一名在任主控；在任助手不超过上限且都有收件箱；名字和别名在在任者之间不重复；个人箱不能与主控箱、广播箱同名。

`since` 决定第一次使用时的基线：加入之前的信视为已读，之后的保留为未读；判断时留 120 秒余量，防止各机器时钟偏差把登记信误判为加入前的旧信。所以主控先 `roster add` 再写登记信，新助手第一次 `inbox` 就能看到。参与方换箱、重新在任、交接后拿到新箱时，箱里已有的信记为已读。

## 8. 不变量

1. 任何时刻恰有一名在任主控；交接是一次原子的花名册改动。
2. 信件只经排他创建产生，永不覆盖、修改、删除。
3. 信头时间来自投递当刻的系统时钟，不手写。
4. 信里不出现凭据的值。
5. 每个参与方的游标、任务、备忘只由本人写。
6. 状态读写失败绝不当作空文件处理（防止已读记录被清空）。
7. 监视循环不派生子进程；要等的路径可写在文件里（`--wait-from`），不出现在命令行上。
8. 交接主控时先备好新旧主控的游标，最后才改花名册，新主控的监视不会把主控箱历史信当新信报。

信任模型：身份由 `--as` 自报，工具防的是误操作（写错收件人、覆盖他人的信、两个主控），不防恶意冒充。需要防冒充时，应由目录权限或宿主隔离来保证。

## 9. 与旧工具共存

| 旧做法 | 行为 | 共存方式 |
|---|---|---|
| 以 `open(...,'xb')` 或 `wx` 排他创建信件的旧投递脚本（取起始号或最大号加一） | 不认编号锁，不管后缀撞号 | 同样排他创建，互不覆盖；`send --start N` 沿用「取不小于起始号的第一个空号」的语义 |
| 按 `to-<箱>-*.md` 列新文件、把已报文件名记在文本里的监视脚本 | 不读控制目录 | 互不影响；`watch` 是它们的超集（另有总账、工作日志、等待文件、提醒） |
| 用编辑器或通用写文件工具直接写信 | 先查空号再写仍有竞态，可能覆盖别人的信 | 改用 `send` |
| 手写信头时间 | 容易估错 | 由 `send` 投递时现取 |

旧工具不认编号锁，也不管后缀撞号；第 5 节第 5 步的复查能兜住大多数情况，剩下的先后顺序由 `doctor` 发现（见该步说明）。
