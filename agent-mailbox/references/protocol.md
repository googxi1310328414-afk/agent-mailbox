# 信箱协议 agent-mailbox/1

本文是协议本身，`scripts/mailbox.py` 是它的参考实现。任何语言、任何客户端，只要按本文读写同一目录，都能与它混用；`adapters/` 下的客户端外壳只是调用这个脚本。

## 1. 目录

信箱是一个**平铺目录**，几方都能读写（同机共享盘，或 WSL 经 `/mnt/<盘>` 访问同一目录）。

| 位置 | 内容 | 谁写 |
|---|---|---|
| `to-*.md` | 信件，一封一个文件，写成后永不改动 | 发信方（只经投递算法创建） |
| `to-*-STATUS.json` | 状态板：长任务的实时快照，整文件原子替换 | 板的写入方 |
| `.agent-mailbox/config.json` | 花名册与设置 | 只有主控或用户（`roster` 子命令） |
| `.agent-mailbox/cursors/<名>.json` | 各参与方的已提醒、已读集合，监视状态 | 本人 |
| `.agent-mailbox/tasks/<名>.json` | 任务清单、等待对象、等待文件 | 本人 |
| `.agent-mailbox/notes/<名>.md` | 续接备忘 | 本人 |
| `.agent-mailbox/presence/<名>.json` | 监视进程登记（pid、主机、心跳） | 本人的 `watch` |
| `.agent-mailbox/notify/<名>.jsonl`、`<名>.archive.jsonl` | 通知流：带序号、只追加；超过 512 KB 时看过的旧条目移到归档 | 发通知的一方与系统（持锁追加） |
| `.agent-mailbox/talk/c<N>.json`、`c<N>.jsonl` | 通话的成员与状态；通话记录（带序号、只追加） | 通话成员（持锁） |
| `.agent-mailbox/queues/<队列>.json`、`<队列>.archive.jsonl` | 工作队列的设置与任务；结束较久的任务归档 | 投放、领取、管理队列的各方（持锁读改写） |
| `.agent-mailbox/requests/<名>.json` | 加入申请 | 申请者；主控或 `roster.admin` 审批 |
| `.agent-mailbox/locks/*.lock` | 编号锁、游标锁、花名册锁、通知锁、通话锁、队列锁（毫秒级持有） | 工具 |
| `.agent-mailbox/log/sent.jsonl` | 投递日志：时间、发件、收件、文件、SHA-256 | 工具（只追加） |
| `.agent-mailbox/log/roster.jsonl` | 花名册改动日志 | 工具（只追加） |

控制目录可用 `--state-dir` 放到别处（例如只读体检时指向临时目录）；但编号锁要对所有写信方可见，正式使用时放在信箱里。

## 2. 信件文件名

```
to-<收件箱>-<线程>-<编号>[-URGENT].md
```

- **收件箱**（box）：小写字母数字，可用 `-` 连接，如 `codex`、`claude`、`kimi-1`。
- **线程**：8 位小写十六进制，区分同一目录里的不同协作。旧式无线程文件 `to-<箱>-<编号>.md` 只读兼容（花名册 `include_threadless: true` 时列入）。
- **编号**：按「箱 + 线程」各自递增，至少 3 位补零（`001`），超过 999 自然变长（`1273`）。同一编号只属于一封信，**不论后缀**：`338.md` 与 `338-URGENT.md` 并存算撞号。
- **后缀**：本工具只生成 `-URGENT`（紧急）；解析时接受 `[-_][A-Za-z0-9_]+` 形式的任意后缀。
- 引用一封信：`941`（在本方各箱里找）、`claude-941`、`codex-338-URGENT`，或完整文件名。

## 3. 收件箱与路由

| 箱 | 归属 | 谁收 |
|---|---|---|
| 主控箱 `controller_box` | **角色**，不属于某个人 | 在任主控收全部来信；交接后新主控接手，箱名不变 |
| 个人箱 `box` | 参与方 | 箱内在任成员；一人独占时不必看标题 |
| 共享箱 | 几个参与方填同一个 `box` | 按标题点名区分 |
| 广播箱 `broadcast_box`（默认 `all`） | 全体 | 全体在任参与方 |

路由依据：本工具投的信在信头「收件：」里写参与方名，收信方按它判断；只有旧信（或别的工具写的信）才回退到解析标题。

标题点名规则：
- 新信标题一律 `# 致 <称呼>[、<称呼>…]：<主题>`。称呼可以是参与方名、显示名、别名，或角色词（`主控`、`全体`、`全体助手`）。
- 称呼按「在任者优先、最长匹配优先」解析；称呼后紧跟的不能是字母数字（`agent-main-20260101` 能匹配 `agent-main`，`pipeline` 不匹配 `pi`）；解析不出时再看其中的 8 位会话号。
- 兼容旧式标题：`# A → B 编号：…`、`# Codex 602：致 X，…`、无 `#` 的首行。

对收件人 X，一封信分为四类：

| 类 | 条件 | `inbox` | `watch` |
|---|---|---|---|
| mine | 标题点名 X（或 X 所属角色词）；或在 X 的独占箱、未点名；或 X 是在任主控且信在主控箱 | 列出 | `MAIL` |
| all | 广播箱里未点名或点名「全体」 | 列出 | `MAIL-ALL` |
| shared | 共享箱里标题没点名任何人 | 列出，标 `[共享]` | `MAIL-SHARED` |
| other | 标题点名的是别人 | 默认不列（`--others` 才列） | 摘要附带（`--others trigger` 才唤醒） |

自己发的信不算自己的未读，也不唤醒自己。

## 4. 信件格式

```
# 致 claude-a：登记 T-123（只读核对）

发件：lead（主控，gpt-5.5，any，会话 7f3a9c21）｜时间：2026-10-26 18:56:32（北京）/ 2026-10-26T10:56:32Z｜编号：to-claude-5e1f0a2b-042｜回复：to-controller-5e1f0a2b-071

正文（Markdown）……

## 附件（投递时实算）

| 文件 | 字节 | SHA-256 |
|---|---|---|
| `D:/run/REPORT.md` | 4674 | `0f14…` |
```

- 第 1 行标题，空一行，第 3 行信头，空一行，正文。
- 信头字段以 `｜` 分隔：`发件`（必有）、`收件`（必有，参与方名，路由以它为准）、`抄送`、`时间`（必有，投递当刻现取，本地时区与 UTC 各一）、`编号`（必有，即文件名去掉 `.md`）、`回复`、`更正`、`紧急`。
- 读旧信时也认 `发信：`、`发信方：`、`发件人：`、`From:`。
- 编码：UTF-8、LF、无 BOM；不得含 U+FFFD；默认上限 64 KB（`max_bytes`）。
- 不得含凭据：内置规则拦截 `sk-`/`sk-ant-` 密钥、`Bearer` 令牌、私钥块、GitHub/AWS/Slack 令牌、JWT；花名册 `secret_patterns` 可追加项目自己的规则。
- 草稿里可写 `{{NUM}}`、`{{FILE}}`，投递时替换成实际编号和文件名。

## 5. 投递算法（排他、不覆盖）

1. 卫生检查：UTF-8、无 BOM、无 CR、无 U+FFFD（`--normalize` 可自动去 BOM、换行改 LF）；渲染后再查大小和凭据。多箱投递先整体校验一遍，避免投了一半才报错。
2. 取编号锁 `locks/send-<箱>-<线程>.lock`（O_EXCL；持有者已死或超过 10 秒视为陈旧；等锁的一方先只看文件年龄，不在持有期间打开它）。锁只用来缩小并发窗口，拿不到时退回为只靠排他创建。
3. 列出同箱同线程**全部后缀**的已用编号，取最大号加一（`--start N` 时取不小于 N 的第一个空号，与「按起始号投递」的旧脚本相同）。
4. 以 `open(path, 'xb')`（Node 为 `flag: 'wx'`）排他创建并一次写入；已存在就把该号记为占用、重新列目录、顺延，最多试 `max_tries` 次。
5. 创建后复查同号的其它后缀文件（防止与不认锁的旧工具同时取到同号）：无后缀者优先，同类按文件名先后；本信该让号时，确认读回内容仍是自己写的才删除，然后顺延重投。这一步只能兜住「对方的文件在本信复查时已经存在」这一种先后顺序：若本信先写了 `NNN-URGENT.md`，只认无后缀文件名的旧工具在复查之后才写 `NNN.md`，仍会同号。`doctor` 会报「同号多信」，引用这类信时要带后缀或写完整文件名。
6. 读回整文件，与写入字节比对，报告字节数与 SHA-256。
7. 追加 `log/sent.jsonl`；更新发件人游标的 `last_sent`。

信一经投递**永不修改、永不删除**。写错了另投一封，信头带 `更正：<原信>`。

## 6. 状态板

```
to-<箱>-<线程>-<KEY>-STATUS.json        KEY：大写字母数字，可用 - 连接，如 PINWIN-W1
```

- 写入：`status put KEY --file x.json`（默认写进主控箱，`--to` 指定别人），整文件原子替换；工具加一个 `_mailbox: {writer, writtenAtUtc}` 字段。
- 用途：长时间执行的进度快照（步数、当前步、最近终态、进程是否存活）。约定每 ≤4 分钟替换一次；它只是快照，原始回执以执行目录为准。
- 不占信件编号，`watch` 不为它唤醒。

## 7. 花名册 config.json

| 字段 | 含义 | 默认 |
|---|---|---|
| `schema` | 固定 `agent-mailbox/1` | |
| `revision`、`updated_at` | 每次改动加一 | |
| `thread` | 8 位十六进制线程号 | 随机 |
| `timezone`、`timezone_label` | 信头本地时间 | `+08:00`、`北京` |
| `controller_box`、`broadcast_box` | 主控箱、广播箱 | `controller`、`all` |
| `include_threadless` | 是否列入旧式无线程信 | `false` |
| `max_assistants` | 在任助手上限（可调） | 8 |
| `max_bytes`、`max_tries`、`pad` | 信件上限、顺延次数、编号最少位数 | 65536、50、3 |
| `policy.assistant_to_assistant` | 助手互通：`allow` / `cc-controller`（自动抄送主控）/ `deny` | `allow` |
| `policy.broadcast` | 谁能广播：`controller` / `anyone` | `controller` |
| `policy.inactive_send` | 不在任者能否发信 | `deny` |
| `policy.talk_max_turns` | 新建通话最多几条发言，到了自动暂停；0 不限（见第 12 节） | 40 |
| `policy.talk_burst` | 新建通话里两方快速来回到「条数/秒数」就自动暂停；`off` 关闭 | `20/300` |
| `policy.max_jobs` | 每人同时最多领几个任务（本人设了 `max_jobs` 的以本人为准）；0 不限 | 1 |
| `quotas` | 配额：`{"<参与方名或 @assistants、@observers>": {"talk": "60/h", ...}}`（见第 12 节） | 无 |
| `secret_patterns` | 追加的凭据正则 | `[]` |
| `presets` | 角色预设的整体改写：`{"assistant": [...], "observer": [...]}`（见第 10 节） | 无（由通信策略推出） |
| `user_token_sha256` | `--as user` 的身份令牌哈希 | 无 |
| `participants[]` | 参与方：`name`、`role`（controller / assistant / former / observer）、`display`、`model`、`harness`、`session`、`box`、`aliases`、`active`、`since`、`until`、`note`；`allow`、`deny`（主控的显式授予、收回）；`token_sha256`（身份令牌哈希）；`skills`（技能标签）、`skills_proposed`（本人申报、待批的技能）、`max_jobs`（同时最多领几个任务）、`auto_take`（空闲时自动接哪些队列的任务，`*` 表示全部） | |

校验（不通过就拒绝写入）：恰有一名在任主控；在任助手不超过上限且都有收件箱；名字和别名在在任者之间不重复；个人箱不能与主控箱、广播箱同名。

`since` 决定第一次使用时的基线：加入之前的信视为已读，之后的保留为未读；判断时留 120 秒余量，防止各机器时钟偏差把登记信误判为加入前的旧信。所以主控先 `roster add` 再写登记信，新助手第一次 `inbox` 就能看到。参与方换箱、重新在任、交接后拿到新箱时，箱里已有的信记为已读。

## 8. 不变量

1. 任何时刻恰有一名在任主控；交接是一次原子的花名册改动。
2. 信件只经排他创建产生，永不覆盖、修改、删除。
3. 信头时间来自投递当刻的系统时钟，不手写。
4. 信里不出现凭据的值。
5. 每个参与方的游标、任务、备忘只由本人写。
6. 状态读写失败绝不当作空文件处理（防止已读记录被清空）。
7. 监视循环不派生子进程；要等的路径可写在文件里（`--wait-from`），不出现在命令行上。
8. 交接主控时先备好新旧主控的游标，最后才改花名册，新主控的监视不会把主控箱历史信当新信报。
9. 通知流、通话记录只追加：序号在锁里取（读最后一条加一），拿不到锁就不写；崩溃留下的残行跳过，下一条另起一行、不重号。
10. 工作队列的每次改动都在队列锁里整文件读改写（原子替换）；同一任务同一时刻至多一人领着，到期的租约在下一次操作时收回。
11. 权限改动只经花名册（`perm` 子命令），与其它花名册改动一样校验、加版本号、记日志，并通知本人。

信任模型：身份由 `--as` 自报，工具防的是误操作（写错收件人、覆盖他人的信、两个主控、越权），不防恶意冒充。
- 给主控和用户设身份令牌（第 10 节）后，冒用这两个身份要先拿到令牌，模型就没法用 `--as` 绕开权限。
- 能直接写目录的人仍然能改文件；要防这种情况，靠目录权限或宿主隔离。

## 9. 与旧工具共存

| 旧做法 | 行为 | 共存方式 |
|---|---|---|
| 以 `open(...,'xb')` 或 `wx` 排他创建信件的旧投递脚本（取起始号或最大号加一） | 不认编号锁，不管后缀撞号 | 同样排他创建，互不覆盖；`send --start N` 沿用「取不小于起始号的第一个空号」的语义 |
| 按 `to-<箱>-*.md` 列新文件、把已报文件名记在文本里的监视脚本 | 不读控制目录 | 互不影响；`watch` 是它们的超集（另有总账、工作日志、等待文件、提醒） |
| 用编辑器或通用写文件工具直接写信 | 先查空号再写仍有竞态，可能覆盖别人的信 | 改用 `send` |
| 手写信头时间 | 容易估错 | 由 `send` 投递时现取 |

旧工具不认编号锁，也不管后缀撞号；第 5 节第 5 步的复查能兜住大多数情况，剩下的先后顺序由 `doctor` 发现（见该步说明）。

## 10. 权限与身份令牌

权限写作 `键[:范围]`。

| 键 | 含义 | 范围 |
|---|---|---|
| `send` | 写信 | 参与方名、角色组 |
| `broadcast` | 广播：写信或发通知给全体 | 不分范围 |
| `notify` | 发通知 | 参与方名、角色组 |
| `talk` | 通话：发起、邀请、发言 | 参与方名、角色组 |
| `talk.audit` | 旁听：读任何通话、看别人的来电队列 | 不分范围 |
| `queue.push`、`queue.take`、`queue.admin` | 投任务、领任务、建队列改设置并代他人处置任务 | 队列名 |
| `status` | 写状态板 | 不分范围 |
| `roster.admin` | 代管花名册：增减助手、改他人信息（不含主控）、审批加入申请 | 不分范围 |
| `*` | 全部 | 不分范围 |

范围写法：
- 角色组：`@controller`、`@assistants`、`@observers`；
- 不写或写 `*`：不限。

判定（命令行与 MCP 完全一致）：
1. 在任主控与用户（`--as user`）永远拥有全部权限；对用户（人）说话总是可以。
2. 不在任的人什么都不能做；唯一例外是 `policy.inactive_send=allow` 时可以写信。
3. 看本人的显式条目（`deny` 收回、`allow` 授予），取覆盖本次操作的最具体一条：点名 3 > 角色组 2 > 不限 1；同样具体时收回优先。
4. 没有显式条目覆盖时，看角色预设。

角色预设：花名册 `presets` 里写了就用它，否则按通信策略推出（与 1.0 行为一致）：
- 助手：`send`、`notify`、`talk`、`queue.push`、`queue.take`、`status`；
  - `policy.assistant_to_assistant=deny` 时，`send`、`notify`、`talk` 只对 `@controller`、`@observers`；
  - `policy.broadcast=anyone` 时加 `broadcast`；
  - `cc-controller` 不改权限，只让助手之间的信、通知、通话自动带上主控。
- 旁听者：`talk.audit`。
- 前任：无。

在通话里发言，要对其中每个在任成员都有 `talk` 权限。邀请别人时，要对被邀请者有 `talk` 权限。

身份令牌：
- 主控用 `perm token <名字|user>` 生成 `amb_` 开头的 44 位令牌，只显示一次（或写进 `--out` 指定的文件，权限位 600）；花名册里只存它的 SHA-256。
- 设了令牌的身份，每次以它操作都要出示令牌：环境变量 `AGENT_MAILBOX_TOKEN`，或 `AGENT_MAILBOX_TOKEN_FILE`、`--token-file` 指向的文件。
- 令牌按凭据规则拦截，不能写进信件、通知、通话。
- 设了按人权限而主控或用户没有令牌时，`doctor` 会提醒。

## 11. 通知流、通话、工作队列、加入申请

通知流 `notify/<名>.jsonl`，每行一条：

```json
{"seq": 3, "at": "2026-11-26T10:00:00Z", "from": "lead", "kind": "job", "title": "队列 review", "text": "…", "urgent": false, "ref": {"queue": "review", "job": 7}}
```

- `kind` 取值：
  - `note`：有人发的通知；
  - `job`、`job-done`、`job-failed`：派活、领取、取消，任务完成，任务失败；
  - `perm`：权限或配额变更；
  - `join`、`joined`：加入申请，加入已批准；
  - `talk-paused`：通话自动暂停（发给主控）；`quota`：谁的配额用完了（发给主控，每个窗口一次）；
  - `job-progress`、`job-blocked`、`job-unclaimed`：任务进度、任务卡住、任务没人能接；`skills`：技能申报、批准与变更。
- 文字最多 4 KB，经卫生检查与凭据拦截。
- 收件人游标里的 `notify_seen` 是已看序号：MCP 送达、命令行 `watch` 报出、`notify list` 列出，都把它往前推。
- 归档：追加之后若通知流超过 512 KB，在同一把锁里把旧条目移到 `<名>.archive.jsonl`。
  - 第一条没看过的、以及倒数第 500 条，从两者中靠前的那条起留在原处；
  - 本人一直不看时，最多为他留 1 万条；
  - 先写归档、再原子替换原文件，中途崩溃只会在归档里多出一份，不会丢；序号不变。
- 读的一方增量读取：文件只是变长了，就只读新增的完整行；被替换（inode 或开头字节变了）或变短才整读。通话记录同样增量读取，不归档。
- 给别人发通知要有 `notify` 权限，发给全体要有 `broadcast`。

通话：
- `talk/c<N>.json` 记 `id`、`topic`、`created_by`、`state`（open / closed）、`members`。每个成员有 `name`、`since`（加入时的序号，之前的消息不算未读）、`left`。
  1.3 起另有 `limits`（`max_turns`、`burst`，建通话时从策略复制）、`paused`（`at`、`by`，自动暂停时为空串、`reason`）、`resumed_at` 与 `resumed_seq`（主控让它继续时的时间与最后一条序号）。
- `talk/c<N>.jsonl` 每行一条：`{"seq", "at", "from", "kind", "text", "reply_to", "urgent"}`。`kind` 取 `msg`（发言）、`join`、`leave`、`close`、`pause`、`resume`；自动暂停的记录 `from` 为空串（显示为「系统」）。文字最多 16 KB。
- 编号 `c<N>` 在 `locks/talk.lock` 里取最大号加一，元数据文件排他创建；发言、邀请、退出、结束在 `locks/talk-c<N>.lock` 里进行。
- 成员游标里的 `talk_seen` 记每个通话的已看序号，未读就是序号之后、别人发的记录。
- **来电队列**：有未读发言的进行中通话，紧急的在前，其余按最早一条未读的时间先来后到。`talk next` 取队首并记为已看；呼叫方看到的「排第几位」就是在这个队列里的位置。
- `talk call` 沿用与对方的一对一通话（按策略抄送主控时允许多一个主控），没有就新建。

工作队列 `queues/<队列>.json`：
- 设置：`lease_seconds`（默认 900）、`max_attempts`（默认 3）、`consumers`（领取名单，空为不限）、`notify`（新任务是否通知可领的人）。
- 任务 `jobs[]`：`id`、`title`、`body`、`from`、`priority`、`to`（指派）、`status`（pending / claimed / blocked / done / failed / cancelled）、`attempts`、`claimed_by`、`lease_until`、`result`、`error`、`log`。
  1.3 起另有 `needs`（所需技能）、`prefers`（加分技能）、`progress`（`pct`、`text`、`at`、`by`）、`blocked`（`at`、`by`、`reason`）、`declined`（`[{who, reason, at}]`）。
- 谁能领（全部满足）：任务在排队；没指派给别人；在领取名单里（若设了）；有 `queue.take`；具备 `needs` 里的全部技能；没拒绝过这个任务；手上在做的任务（跨全部队列、已领未卡住的）少于本人的 `max_jobs`（没设就看 `policy.max_jobs`）。主控与用户不看技能和上限。
- 领取顺序：优先级高的先；同优先级里指派给自己的先；再看 `prefers` 命中本人技能多的；最后按 `id`。`take --job N` 领指定的那一个，领不了就报原因；领不到时返回各个排队任务领不了的原因与个数。
- 领取时 `attempts` 加一。租约到期时还有次数就放回排队，否则判失败并通知投放者。`release` 放回且不算一次尝试，`fail --retry` 还有次数就放回排队。
- `decline`：领了又不适合，放回排队且不算一次尝试，并记进 `declined`，以后不再分给他；没领的也可以先拒绝（要有 `queue.take`；指派给别人的任务不用拒绝）。能接的人都拒绝了，就通知主控（`job-unclaimed`），否则再通知手上有空的人。
- `progress`：记进度并顺带续租；投放者收到 `job-progress`，同一任务 5 分钟内最多一次。
- `block`：转为 blocked，租约暂停（`lease_until` 清空），通知投放者与主控（`job-blocked`）。`unblock` 由领取方、投放者或有 `queue.admin` 的人做，回到 claimed 并重新计租约。卡住的任务也能 `done`、`fail`、`release`、`decline`。
- 新任务只通知能接的人：先找手上有空的，都忙就通知所有能接的；没人能接就通知主控（`job-unclaimed`），投放结果里也写明能接的人。
- 队列文件只在真有改动时重写：空领一次不会改写文件、惊动别的等待方。
- 已结束的任务保留最近 100 个，更早的移到 `<队列>.archive.jsonl`。
- 排队中的任务最多 500 个；内容与结果各最多 16 KB。

技能：
- 标签写法：小写字母或数字开头，可含 `. + # _ -`，最长 32 个字符，每人最多 32 个。
- 申请加入时 `join --skills` 申报，主控 `roster approve --skills` 确认或改写。已在任的人用 `roster skills <本人> --set` 申报，记进 `skills_proposed`，主控 `--approve` 采纳、`--reject` 驳回；主控、用户或有 `roster.admin` 的人也可直接 `--set`。
- 本人可以改自己的 `auto_take`；`max_jobs` 由主控、用户或有 `roster.admin` 的人设。
- 自动接单只在 MCP 服务里生效：模型调 `mailbox_wait`（空闲）且手上的任务少于上限时，服务按上面的规则替本方领最合适的一个，连同同时到的事件一起交出；这次回应没送到（调用被取消、发送失败）就把任务放回排队。

加入申请 `requests/<名>.json`：
- 字段：`{"name", "model", "harness", "display", "note", "role", "skills", "at", "status": "pending|approved|rejected", "decided_by", "decided_at", "reason", "skills_approved"}`；`skills` 是申报的技能，`skills_approved` 是批准时确认的技能（1.3 起）。
- 同时待批的申请最多 20 个。重复申请只刷新内容，不重复通知。

## 12. 门铃、通话上限与配额

门铃 `bell/<名>`：
- 发言、邀请、暂停与继续、发通知、投信之后，写入方给每个收件方的门铃文件追加一个字节（自己的不按）；文件到 64 KB 就截短，截短本身也算响。
- 等待方先记下本方门铃的 inode、大小与修改时间，再做完整检查；之后每 0.1 秒看一眼，变了就立刻重查。MCP 服务的 `mailbox_wait`、`mailbox_call`、队列等待，命令行的 `watch`、`talk call/say --wait`、`talk wait`、`talk next --wait`、`queue take/push --wait` 都这样等。
- 门铃只是提示，收件一律以状态为准：漏响（比如写入方是旧版本）只是退回原来的轮询间隔，多响只是多查一次。只读模式不写门铃。

通话上限与自动暂停：
- 每条发言之后检查：发言数（用户说的不算）到了 `limits.max_turns`；或只有两方、近 `burst` 秒内（且在 `resumed_seq` 之后）来回了 `burst` 条、其间用户没说话。满足其一就把 `paused` 写进元数据，追加一条 `pause` 记录，按响全体成员的门铃，并通知主控。
- 暂停中只有主控和用户能发言；其他人发言、邀请别人、另开成员相同的通话都会被拒。
- `talk pause` 由主控或用户手动暂停。`talk resume` 清掉 `paused`，记下 `resumed_at`、`resumed_seq`：带 `--max-turns` 就改上限（0 不限），不带时若因上限而停，上限改为「已有条数 + 策略条数（至少 10）」；带 `--burst` 改快速来回的门槛。
- 没有 `limits` 的通话（1.3 之前建的）不受限。

配额：
- 花名册 `quotas` 的键是参与方名或 `@assistants`、`@observers`，值是 `{动作: 写法}`。动作：`talk`（每条发言）、`call`（每次新开通话）、`send`（每次发信，演练不算）、`notify`（每次发通知）、`queue.push`（每个任务）。写法「次数/窗口」，窗口 `m`、`h`、`d`；`none` 明确不限（压过角色组的配额）。
- 判定：点名的优先于角色组的；主控与用户不受限。
- 用量记在 `usage/<名>.json`：每个动作在窗口内的时间戳（最多「次数」个），在 `locks/usage-<名>.lock` 里读改写。用完时操作被拒，并在每个窗口里最多通知主控一次（`warned`）。
- `perm quota` 由主控或用户设置，`perm show` 显示生效的配额与本窗口已用次数。
- 批准时按申请加入花名册：已是前任的，重新在任，旧箱里的历史信记为已读。可顺带写 `allow`、`deny`，这一步只有主控能做。
